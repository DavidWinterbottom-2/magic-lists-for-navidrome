- 2026-09-11 | code-review | backend/recipe_manager.py MATH-expression evaluation (2/N) | The 2026-08-17 review logged `recipe_manager.py`'s `eval(expression, allowed_names, {})` in `_evaluate_math_expressions` as "currently unreachable"; the previous round's re-verification found it live instead (3 bundled recipes — genre_mix_v1_001, radio_v1_001, this_is_v1_009 — carry `{{MATH:...}}` expressions evaluated on every curation request). Replaced `eval()` with `_safe_eval_math()`: parses the expression with `ast.parse(mode="eval")` and walks only whitelisted node types (numeric constants, the binary/unary ops, and calls to a small function whitelist — abs/round/min/max/ceil/floor/pow/sqrt, matching the original `allowed_names` even though bundled recipes only use max/ceil/floor) — anything else (attribute access, subscripts, comprehensions, calls to a non-whitelisted or non-`Name` callable) raises `ValueError` instead of executing, which `_evaluate_math_expressions`'s existing `except Exception` already degrades to the original literal (same failure mode as any other malformed expression, not a new one). New regression test `test_a_disallowed_expression_is_rejected_not_executed` covers 4 payloads (`().__class__`, `__import__('os').system(...)`, `open('/etc/passwd').read()`, a list comprehension) and confirms each is left intact rather than executed. Full suite (312 tests) green, `ruff check --select=E9,F63,F7,F82` clean (magic-lists-for-navidrome 0.3.10)
